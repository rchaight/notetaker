# Spec 01 — Vault context files: `_index.md` per folder + root `CLAUDE.md`

## Scope

The app maintains, inside the vault, machine-written tables of contents that
let any agent (Claude Code pointed at the folder, or the MCP server) navigate
the vault without scanning every file.

### `_index.md` — one per folder that contains notes (including the root)

- **Fully app-owned.** First line: `<!-- Auto-generated by Notetaker — do not
  edit; changes are overwritten. -->`
- Content, rendered deterministically (stable ordering: subfolders A–Z, then
  notes A–Z by filename):
  - `# Index — <folder name>` (root: `# Index — Vault root`)
  - Subfolder list: `- 📁 [<name>/](<name>/_index.md)` — link to the child index.
  - Note list, one line each:
    `- [<title>](<url-encoded filename>) — <summary> · <#tags> · <N open tasks> · <yyyy-mm-dd modified>`
    - `title` = indexed note title; `summary` = first non-empty, non-heading,
      non-task body line, truncated to 120 chars (omit segment if none).
    - Omit the tags / task-count segments when empty; task count from the index.
    - Locked notes: `- 🔒 <title> — locked note` (no summary, no link body read).
- **Rendering is a pure function** `IndexFileRenderer` in **IndexKit**
  (it already owns `NoteRecord`): input = folder path, `[NoteRecord]`,
  subfolder names, per-note open-task counts + tags; output = String.
  Unit-tested in IndexKit (ordering, truncation, locked, empty folder,
  URL-encoding of spaces).

### Generation driver (app target, `VaultIndexService`)

- After each `reindexFromDisk()` settles, debounce ~2 s, then for each folder
  compute the rendered index and **write only if the content differs** from
  what's on disk (compare-before-write is the loop breaker: write → observer
  fires → reindex → regenerate → identical → no write → quiescent).
- Writes go through the existing coordinated-write path (`VaultFileStore`).
- Folders whose notes all disappeared: delete the stale `_index.md`.
- Gate everything on `@AppStorage("claudeIndexFiles")` (Bool). **Default
  true.** When toggled off, stop generating; leave existing files in place
  (Settings copy explains that — spec 03 owns the UI).
  Expose the key as a constant (e.g. `VaultIndexService.indexFilesKey`) for
  spec 03 to reference.

### Exclusion from the app's own surfaces

- Files named `_index.md` must NOT appear as notes: excluded at the
  **`VaultFileStore` enumeration choke point** in VaultKit, so the indexer,
  notes list, recents, search, and task extraction all skip them at once.
  Builder must verify every listing path flows through that choke point and
  add the filter to any that don't (metadata-query observer results included —
  changes to `_index.md` may still *trigger* reindex, they just never index).
- `CLAUDE.md` at the root is NOT excluded — it stays a normal, editable,
  indexed note so the user can tune Claude's instructions in-app.

### Root `CLAUDE.md` seeding

- On vault start, if `CLAUDE.md` does not exist at the vault root, create it
  once (coordinated write). **Never overwrite an existing one.**
- Seed content (write exactly, adapting the vault-name line):
  - What this vault is (markdown notes; plain files are the source of truth).
  - "Read `_index.md` in a folder before opening its notes; the root
    `_index.md` maps the vault."
  - The task grammar table (`- [ ] text >due !p1 #tag @person ?kind &every …
    ^id blockedby:^id ✅date`) with one-line token meanings.
  - Conventions: daily notes naming, `Meetings/<Name>.md`, `Inbox.md`,
    projects = notes with `project` frontmatter.
  - "Prefer the `notetaker` MCP tools (search, tasks) when available; fall
    back to reading files. Never edit `_index.md` (auto-generated). Locked
    notes (🔒) are private — do not attempt to read them."

## Acceptance criteria

1. IndexKit tests cover `IndexFileRenderer` (≥5 cases listed above); all pass.
2. Launch app against a test vault → every folder with notes gains a correct
   `_index.md`; root gains `CLAUDE.md`; second launch with no vault changes
   rewrites nothing (verify by mtime).
3. Editing a note updates only the affected folder's `_index.md` within ~5 s;
   no reindex/regenerate loop (observe quiescence in logs/fs).
4. `_index.md` never appears in the notes sidebar, recents, search results,
   or the To-Do list; `CLAUDE.md` appears and is editable.
5. A user-modified `CLAUDE.md` survives restarts untouched.
6. `scripts/verify.sh 1 --install` green.
